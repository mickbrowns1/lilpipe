How to use Trickle

Trickle lets you build a data pipeline (source → steps → destination), run it, and see exactly what happened to the data. Click a question to open it.

Getting started

What is this for?

Testing before you ship. You can check how a Lua serializer maps a vendor log to OCSF, try Vector filter/remap/sample/dedupe steps, and measure how much volume a pipeline removes, all without touching a tenant or sending data anywhere.

What is the quickest way to try it?
  1. Leave the source as Raw record(s) (a sample Cato event is preloaded) and the second box as Lua serializer.
  2. Press ▶ Run pipeline.
  3. Read the Serializer: before / after tab below the pipeline.
What are the three kinds of boxes?

Source is where data comes from. Steps change it (filter, remap, sample, dedupe, or a Lua serializer). Destination is where it ends up. Click any box to edit it on the right. Click the + between boxes to add a step.

Testing a Lua serializer

How do I test my own serializer?
  1. Click the Source box and paste a real vendor event as JSON (one object, an array, or one per line).
  2. Click the Lua serializer box and paste your code, or type a file path (re-read on every run, so you can edit in your own editor and press Run again).
  3. Your code must define function processEvent(record) that returns a table.
  4. Press Run.
What do MOVED, TYPE CHANGED, NOT CARRIED and ADDED mean?

MOVED: same value, new field name (src_ip → src_endpoint.ip). TYPE CHANGED: same value, different type ("47046" → 47046). CHANGED: same field, new value. NOT CARRIED: the value is not in the output, so it was dropped or transformed. ADDED: new in the output, such as class_uid or dataSource.*. SAME, UNMAPPED and EMPTY are hidden by default; click their chips to show them.

Why does a field I converted show as NOT CARRIED plus ADDED?

The comparison matches by value. If your serializer transforms a value (for example risk_level "Medium" becomes severity_id 3, or an ISO time becomes epoch milliseconds), the original value no longer appears, so it shows as NOT CARRIED and the new field as ADDED. That is expected.

What are the PASS/FAIL checks above the diff?

Quick OCSF sanity checks on every record: class, category and activity are set; type_uid = class_uid × 100 + activity_id; time is a number in epoch milliseconds; metadata.version and metadata.product.* are set; and dataSource.category/vendor/name are set and match metadata.product (needed for events to show up in XDR search). A FAIL shows which record failed first.

What is the “Console lint” box?

It flags code the DPM console would likely reject when you save the script: a string continued with .. at the end of a line, // and other Lua 5.3 syntax, $something anywhere in the file, an apostrophe in a comment, or missing dataSource.* fields. Fix these before pasting into the console.

How is this different from the real DPM runtime?

The serializer runs on a local LuaJIT, not inside DPM. json and log work, but DPM-only modules such as hmac and codec do not. Treat this as a fast check, and still save the script in the console as the final test.

The buttons

Run, Validate and View config: what is the difference?

Run pipeline does the work and shows the results. Validate checks without running: real Vector checks your config and VRL, and the Lua serializer is checked for loading and lint. View config shows the Vector config file generated from your pipeline. It is empty for a raw record plus serializer, because Vector is not used in that case.

What do I see after a run?

For Vector steps: events in and out after every stage, the volume saved (as JSON size), and sample events at each stage (Stage events tab). Warnings from Vector are in the Vector log tab. With a serializer: the Serializer: before / after tab, with a switch to see the full OCSF output or the raw input.

Vector steps (filter, remap, sample, dedupe)

How do I test noise reduction?

Set the source to Sample log generator (or paste your own lines with File), add steps, and press Run. Each box shows in → out with the percentage removed, so you can see which step does the work. Use the Save to file or Print to screen destination to see the final events.

What do the step types do?

Filter keeps events where a VRL condition is true. Remap runs a VRL program to parse, rename, add or delete fields (there is a preset menu). Sample keeps 1 of every N events. Dedupe drops repeats that have the same values in the fields you list. Order matters: a filter on .severity only works after a remap has parsed it.

What does the Dev/null destination mean?

The events go nowhere and nothing is stored, so you can test freely. You still get all the counts and the before/after view, because those are measured inside the pipeline.

A step shows warnings or the Vector log has ERROR lines. What happened?

Usually a VRL step failed on some events, for example parse_json on a line that is not JSON. Those events pass through unchanged and the run continues. Open the Vector log tab for the message, then fix the VRL or filter those events out first. Validate catches syntax errors before you run.

Why does an HTTP source run take a few seconds?

Lab starts a temporary Vector listener, sends your body, then stops it a few seconds later. A listener never finishes on its own, so it is stopped after the input is used up.

Files, saving and setup

How do I use my own log file or serializer file?

Running in Docker: put the file in the data folder next to docker-compose.yml and type /data/yourfile in the app. Running without Docker: type the normal path, for example ~/Downloads/sample.log. You can also just paste text into the box.

How do I save and reuse a pipeline?

Type a name in Saved pipelines (left) and press Save. Click a saved pipeline to load it, or × to delete it. They are stored in the pipelines folder, so you can share them or keep them in Git. Files from Save to file go to the output folder.

It says Vector or Lua was not found, or “server offline”.

In Docker both are included; check the container is running with docker compose ps. Without Docker, install them with brew install luajit and brew trust vectordotdev/brew && brew tap vectordotdev/brew && brew install vector, then restart server.py. “Server offline” means the app itself is not running.

Is my data sent anywhere?

No. Everything runs on your machine and the app only accepts connections from it. Do not paste real customer logs into anything you plan to share or commit.
